# follow-the-plan

1. State the plan: list the steps of the task (from the user's plan or the issue/PR scope) before starting.
2. State which step you are on before starting it.
3. Execute that step; do not start another step until this one is done.
4. Mark each step done after completing it.
5. Ask for plan approval ONLY if you hit an open question you can't resolve (you don't understand what to do). If the plan is clear, proceed without asking.
6. If a step cannot be completed — missing information, a command you can't run, a blocked action, or an implementation you can't do — STOP. Say exactly which step and why. Do not start another step or implement something "in the meantime"; the user decides how to proceed.
